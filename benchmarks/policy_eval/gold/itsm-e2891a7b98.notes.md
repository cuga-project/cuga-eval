## Conventions used

- Each rule written from prose covers one statement, and its quote is word for word from that statement.
- Rules read from tables and lists (`"by": "code"`) cite all the rows they read, plus the sentence that introduces the
  table (3.1:4, 4.2:8, 3.3:2).
- Section headings that the converter split as statements (3.1:1, 3.2:1, 3.3:1, 4.1:1, 4.2:1, 5.1:1, 8.1:1, 8.2:1):
  - They have no real type. They get `definition` by convention.
  - Their coverage is `out_of_scope`.
- Role rules are written only for tables that the role table names (incident, problem, change, knowledge, CMDB =
  `configuration_item`). The parts that need a tool-to-table mapping the policy does not state stay `verify`. Examples:
  "system administration settings", and Manager/Agent writes to users, groups, SLA definitions and other tables.
- §9 rules that repeat the tool enum (9:1–9:4, 9:6, 9:10, 9:11) are included for completeness. The pipeline skips such
  rows by design, so a scorer may treat these 14 rules as optional.

## Conflicts inside the policy

There is no pair of statements that contradict each other, so every rule keeps `may_deny: true`. Points of tension
and gaps between the policy and the tools:

- **9:7 against the tool schema, with 3.3:7.** The policy lists `resolution_code` values `fixed, workaround,
  not_reproducible, closed_by_caller`. The `create_incident`/`update_incident` enums contain none of these values.
  3.3:7 makes `resolution_code` mandatory for `resolved`. So no `update_incident` call can resolve an incident without
  breaking either the policy list or the tool schema. The rule is kept as `schema_conflict`, as SKILL.md says.
- 3.1:3 makes `opened_by` mandatory, but `create_incident` has no `opened_by` argument. No rule covers it.
- 6:4 "escalation flag" and 9:8 `change_request.type` have no tool argument.
- 3.3:6 allows `resolved → closed`, but 3.3:8 says closure happens after 72 hours. This is a conflict only if 3.3:8
  means "not before 72 hours".
- 2:7 "Public Knowledge" and 7:1 "state = published" are two different conditions. Both are kept.
- Wording mismatches:
  - 6:3 says "Incident is in stage = on_hold", but the incident field is `status`.
  - 4.2:6 says `workaround_notes`, but the field is `workaround`.
  - 9:5 leaves out `canceled`, which the tool accepts, so the policy list is narrower than the tool.
