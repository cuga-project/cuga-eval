The ITSM policy as a hybrid graph, used by the agent at every lifecycle hook

Built by hand from the EnterpriseOps-Gym ITSM policy (docs/analysis/samples/enterpriseops-gym/itsm_policy.md, 10,668 characters). Each node is one policy rule, checked by the cheapest checker that can decide it. Step through the hooks to see what the system looks up and decides for the task on slide 11 of the deck. Click any node for its source line and compiled form.

What the system indexes for this policy

The system, not the agent, finds every rule that can block an action, by exact keys. The agent can only ask the graph for guidance (policy_next_steps(), policy_search()).

Notes

Illustrative, not built. The graph, the Cedar text and the check results are drawn by hand to show the idea. Values marked inferred come from the task's SQL verifiers, not from the seed database (for example: priority high implies urgency medium with impact high; SLA_002 is the SLA the verifier expects). The task file lists 12 SQL verifiers, but only 3 distinct checks (incident update, SLA link, notification), each repeated 4 times.
